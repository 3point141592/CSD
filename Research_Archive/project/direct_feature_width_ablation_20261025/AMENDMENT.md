2026-10-25 pretraining amendment
===============================

After the original lock was written and while all 120 jobs were still pending, the user explicitly authorized concurrent GPU execution with the already running `train.py --device cuda` job. GPU inspection showed 10,644 MiB used and 21,544 MiB free on the RTX 5090, at 34% utilization. The waiting worker exited via its graceful STOP_AFTER_JOB marker without training any model. No other process was interrupted.

The only protocol change is the scheduling rule: the successor worker does not wait for that external process. The two model architectures, data, seeds, optimizer, training steps, evaluation and analysis are unchanged. A pilot-resume guard was also repaired before any training, so a completed pilot pair is read from its saved timing record if a later pilot pair needs retry. The initial lock is preserved as `lock.initial.json`; `lock.json` records the amended source hashes and the initial lock hash. The old worker's launch/log/ended-lock files remain in place.

Concurrent timing can differ from the September 2026 run, so measured pilot wall time and VRAM, not the earlier estimate, will govern resource reporting. No result will be mixed with a changed numerical protocol.

The first concurrent 32D pilot trained but failed at the checkpoint round-trip: `torch.load(weights_only=True)` rejected a `TorchVersion` object in the saved metadata. Its failed attempt and traceback remain in `attempts/` and the manifest. Before any job was accepted as complete, `run.py` was amended to convert the runtime metadata to plain JSON types before saving, matching the completed September runner's approach. The numerical model, training and evaluation functions did not change. The previous lock is preserved as `lock.amendment1.json`; the next pilot retries the same fixed seed and architecture.

The failed attempt, including its complete checkpoint, metrics, curves, hashes and traceback, is preserved. The runner now uses the September study's bounded atomic-rename retry helper and accepts completed jobs under the previous source lock after verifying that frozen prior lock and source. The previous source and lock are preserved as `run.amendment2.py` and `lock.amendment2.json`. Model construction, inputs, normalization, training and evaluation did not change. The seed-479 completed payload is committed from the preserved attempt after hash verification, rather than retrained or zero-filled.
